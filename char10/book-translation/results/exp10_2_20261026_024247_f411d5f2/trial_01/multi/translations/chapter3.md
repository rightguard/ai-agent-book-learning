# 第三章：优化推理时延

模型一旦能正常工作，接下来的挑战就是速度。目标是降低**时延**，同时提高**吞吐量**，即系统每秒完成的请求数量。这两者往往相互制约。

最重要的技巧是**KV 缓存**。在推理过程中，模型如果不使用缓存，每一步都需要重新计算之前所有词元的注意力。通过缓存过去词元的键和值向量，模型只需处理最新的词元，这能大幅降低长提示词的时延。

```python
def decode_step(new_token, kv_cache):
    q, k, v = project(new_token)         # only the new token
    kv_cache.append(k, v)                # reuse past keys and values
    return attention(q, kv_cache.keys, kv_cache.values)
```

第二个技巧是**批处理**：将多个提示词分组处理，让硬件保持忙碌状态。更大的批次能提高吞吐量，但可能会增加单个请求的时延，因此服务系统需要仔细调整批次大小。

关键在于推理性能是一种平衡。我们每避免重新计算一个词元，每优化一批提示词，都能同时推动系统向更低时延和更高吞吐量迈进。
